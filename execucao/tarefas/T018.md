## Entrega
1. Criar runtime puro para `QuestProgress` com estados locked → available → active → completed.
2. Ativar a quest executando as `entryActions` do estágio atual uma única vez.
3. Concluir estágio executando `completionActions`, aplicando checkpoint e entrando no próximo estágio.
4. Produzir IDs estáveis de execução para impedir duplicação por evento repetido.
5. Manter semântica concreta das ações e matching de objetivos fora deste ticket.

## Critérios de aceite
- [x] Prerequisite ausente mantém locked; concluído libera available.
- [x] Ativação emite entryActions uma vez.
- [x] Conclusão respeita ordem completion → checkpoint → próximo estágio → entry.
- [x] Repetição de conclusão antiga não duplica ação nem progresso.
- [x] Estágio terminal conclui a quest.
- [x] Runtime fica em packages/sim sem Phaser/DOM/rede.
